### 1.2 搜尋列與篩選器渲染邏輯

| 元素 | 資料來源 | 渲染規則 |
|------|----------|----------|
| 搜尋框 | 本地 state | `input[type=text]`，placeholder=`i18n('marketplace.search_placeholder')` — "搜尋 Bot 名稱、能力..." |
| 能力篩選 | `GET /api/rental/marketplace?capabilities=...` 支援的值 | 多選下拉：`python_exec`, `web_browse`, `vision`, `file_io`, `reasoning`, `coding`, `tts`。每個選項顯示圖示 + 名稱。選中後渲染為 chip |
| 排序選項 | 前端常量 | 下拉：`rating_desc`（⭐ 評分最高）、`rate_asc`（💰 費率最低）、`total_rentals_desc`（🔥 最熱門）、`created_at_desc`（🆕 最新上架） |
| 費率範圍滑桿 | 前端 state，提交為 `rate_min` / `rate_max` 查詢參數 | 雙滑桿，步進 1 e幣。標籤顯示 `{min} – {max} e幣/1K tokens` |

**篩選觸發**：任何篩選器變更 → debounce 300ms → `GET /api/rental/marketplace?keyword=X&capabilities=Y&sort=Z&rate_min=A&rate_max=B&page=1&limit=20`

### 1.3 Listing 卡片渲染邏輯

**資料來源**：`GET /api/rental/marketplace` 回傳的 `listings[]` 陣列

```
┌──────────────────────────────┐
│  [Bot Avatar]  Bot 名稱       │
│  ────────────────────────     │
│  🤖 模型: Claude Opus 4.6    │
│  💰 費率: 10 e幣/1K tokens    │
│  💎 押金: 200 e幣             │
│  ⭐ 4.8 (23 次租借)           │
│  ────────────────────────     │
│  [python] [web] [vision]      │
│  ────────────────────────     │
│  [🟢 可租借] 或 [🔴 已出租]   │
└──────────────────────────────┘
```

| 欄位 | API 欄位 | 渲染規則 |
|------|----------|----------|
| Bot Avatar | `listing.avatar` 或 `listing.character` 預設圖 | 圓形 48×48px。若無 avatar，用 character type 的預設 SVG |
| Bot 名稱 | `listing.title` | 最多 2 行，超出 `text-overflow: ellipsis` |
| 模型 | `listing.model_detected` | 前端 `formatModelName(model)` 轉人類可讀名稱。未知模型顯示原始字串 |
| 費率 | `listing.rate_mli_per_ktoken` | **轉換公式**：`rate_ecoin = rate_mli / 1000`。顯示 `{rate_ecoin} e幣/1K tokens` |
| 押金 | 計算值 | **公式**：`deposit_ecoin = rate_mli * 20 / 1000`。顯示 `{deposit_ecoin} e幣` |
| 評分 | `listing.avg_rating` | ⭐ + 數字（1 位小數）。`null` 或 0 → 顯示 "尚無評分" |
| 租借次數 | `listing.total_rentals` | `({total_rentals} 次租借)` |
| 能力標籤 | `listing.capabilities` | 遍歷 `capabilities` 物件，`supported === true` 的 key → 渲染為 chip。每個 chip 有固定顏色映射：`python_exec`=綠、`web_browse`=藍、`vision`=紫、`reasoning`=橙、`coding`=黃 |
| 可用性狀態 | 後端推算（有無 active contract） | 🟢 `可租借`：無 active contract 時。🔴 `已出租`：有 active contract 時，按鈕 disabled |

### 1.4 可用性狀態特殊渲染

**場景 C3/D2/D6/L5**：Listing 不可租借時的卡片渲染

| 狀態 | 視覺處理 | 按鈕狀態 |
|------|----------|----------|
| `status=listed` 且無 active contract | 正常亮度 | 🟢 `可租借`，可點擊 |
| `status=listed` 且有 active contract | 卡片半透明 `opacity: 0.6` | 🔴 `已出租`，`disabled`，tooltip="此 Bot 目前已被租借" |
| `status=paused` | **不渲染**（marketplace API 不回傳 paused listings） | — |
| `status=delisted` | **不渲染** | — |
| `status=draft` / `status=interview` | **不渲染** | — |

### 1.5 自租禁止渲染

**場景 C1**：Owner 瀏覽自己的 Listing

- 前端檢查：`listing.owner_user_id === currentUser.id`（注意：公開 API 不回傳 `owner_user_id`，需後端額外回傳 `is_own: true` 標記）
- 若 `is_own === true`：
  - 卡片右上角顯示 `👤 你的 Bot` 角標
  - 點擊 → Modal 中「租借」按鈕替換為 disabled 狀態 + tooltip `"無法租借自己的 Bot"`
  - 後端兜底：`POST /api/rental/contract` 回傳 `self_rental_forbidden` → Toast `"無法租借自己的 Bot"`

### 1.6 冷卻期封鎖渲染

**場景 B8**：Renter 24h 內嘗試再租同一 Listing

- `POST /api/rental/contract` 回傳 `cooldown_active`，payload 含 `cooldown_expires_at`
- Modal 中「租借」按鈕 disabled
- 按鈕下方顯示：`"冷卻期中，{remaining_time} 後可再次租借"` — `remaining_time` 以 `Xh Ym` 格式動態倒數

### 2.2 費率區域渲染邏輯

| 欄位 | 計算方式 | 渲染規則 |
|------|----------|----------|
| 費率 | `listing.rate_mli_per_ktoken / 1000` | `{rate} e幣/1K tokens` |
| 市場建議 | `GET /api/rental/listing/:id` 回傳 `pricing_suggestion`，或前端呼叫 pricing-advisor | 顯示範圍 `{min_suggested} – {max_suggested} e幣/1K`。**偏離標記**：`rate < min_suggested` → 🟢 `低於建議`；`rate > max_suggested * 2` → 🔴 `遠超建議`；其他 → 🟡 `合理範圍` |
| 押金 | `rate_mli * 20 / 1000` | `{deposit} e幣 (≈ NT${deposit/100})` — 根據固定匯率 1 TWD = 100 e幣 |
| 平均對話費用 | 後端 `listing.avg_tokens_per_conversation`（有歷史資料時）或預設 3,400 tokens | `平均每次對話 ≈ {tokens} tokens ≈ {tokens * rate / 1000} e幣` |
| 租借時長範圍 | `listing.min_rental_minutes` / `listing.max_rental_minutes` | 轉為小時：`min_hr = min_min / 60`，`max_hr = max_min / 60`。預設 0.5h – 168h |

### 2.3 時長選擇與費用預估渲染

| 元素 | 渲染規則 |
|------|----------|
| 數字輸入框 | `input[type=number]`，step=0.5，min=`min_rental_hours`，max=`max_rental_hours`。單位：小時 |
| 滑桿 | `input[type=range]`，同步更新數字框 |
| 預估總費用 | **公式**：`estimated = deposit_ecoin + (duration_hours × avg_tokens_per_hour × rate_ecoin / 1000)`。`avg_tokens_per_hour` 預設 60,000（約每分鐘 1,000 tokens 的 typical chat） |
| 餘額充足性 | `GET /api/wallet/balance` 取 `balance_mli`。**判斷**：`balance_mli >= deposit_mli + (rate_mli * 60)`（60K buffer）。✅ 顯示綠色 "足夠"；❌ 顯示紅色 "餘額不足，需 {required} e幣，目前 {current} e幣"，且「確認租借」按鈕 disabled |

### 2.5 隱私提醒 + 年齡確認渲染

**根據 BRM 設計文件 §11.4 + 設計決策 #21**

| 元素 | 條件 | 渲染規則 |
|------|------|----------|
| 隱私提醒區塊 | 每次租借必顯示 | 黃底告警框。checkbox「我已了解並同意」必須勾選才能啟用「確認租借」按鈕 |
| 年齡確認 Modal | `user.age_confirmed_at === null`（首次租借） | 獨立 Modal 疊加在 Detail Modal 之上。「我已年滿 18 歲」確認後 → `POST /api/user/confirm-age` 記錄 IP + timestamp → 關閉 → 回到 Detail Modal |

### 2.6 租借確認流程渲染

**場景 A6, E2, F1**：點擊「確認租借」

1. 按鈕變 loading spinner + 禁用
2. `POST /api/rental/contract` → body: `{ listingId, planned_duration_min, renter_device_id }`
3. **成功**（status 200）：
   - Modal 替換為成功動畫 ✅
   - 顯示：`"租借成功！Bot 已加入你的裝置。"` + 合約摘要
   - 按鈕組：`[🗣️ 開始聊天]` `[📋 查看合約]`
   - 3 秒後自動關閉 Modal
4. **失敗回應渲染**：

| API 錯誤碼 | 渲染 |
|------------|------|
| `self_rental_forbidden` | Toast 紅色：`"無法租借自己的 Bot"` |
| `insufficient_balance` | 跳轉到 §2.4 餘額不足卡 |
| `listing_already_rented` | Toast 紅色：`"此 Bot 已被其他人租借"`，Modal 刷新 → 卡片狀態更新為 🔴 已出租 |
| `listing_not_available` | Toast 紅色：`"此 Listing 已下架或不存在"` |
| `cooldown_active` | 跳轉到 §1.6 冷卻期封鎖 |
| `duration_below_listing_min` | Toast 橘色：`"最短租借時間為 {min} 分鐘"` |
| `duration_above_listing_max` | Toast 橘色：`"最長租借時間為 {max} 分鐘"` |
| `age_confirmation_required` | 觸發年齡確認 Modal |

### 3.2.3 「提前結束」確認 Dialog

### 10.2 Vault 隔離渲染邏輯

**根據 BRM 設計決策 #18（HARD isolation）**

Owner 在 env-vars.html 設定變數時的額外 UI：

```
┌─────────────────────────────────────────────────┐
│  新增環境變數                                    │
│  ──────────────────────────────────              │
│  Key: [SECRET_API_KEY        ]                   │
│  Value: [sk-test-123         ]                   │
│  ──────────────────────────────────              │
│  🔒 隔離設定 (Bot 租借)                          │
│  ○ 自動隔離 — 含 KEY/SECRET/TOKEN/PASSWORD       │
│    的變數名自動對租借 Bot 隱藏                    │
│  ○ 手動白名單 — 勾選允許租借 Bot 讀取             │
│    □ 允許租借 Bot 讀取此變數                      │
│  ──────────────────────────────────              │
│  [取消]              [儲存]                      │
└─────────────────────────────────────────────────┘
```

**隔離規則**（BRM §9.11, §11.4）：
- 變數名匹配 `*_KEY`, `*_SECRET`, `*_TOKEN`, `*_PASSWORD` → 預設 blocked
- Owner 可在 listing 編輯時的 `allowed_vars` 白名單中手動加入
- 租借 bot 讀 `/api/device-vars` 時：
  - 被隔離的 key → 不回傳
  - 白名單 key → 正常回傳
  - 鎖定狀態（`locked = true`）→ 回傳 `locked_error`

### 10.3 鎖定狀態渲染

**場景 I8–I9**

- 列表每行顯示 🔒 圖示

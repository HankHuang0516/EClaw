# 自動核准規則

Hank 2026-11-10 指示：「你自動判斷核准 不需要由我同意」。節日禮包活動因此不再逐檔請他核准，由 `lib/policy.js` 判斷。下面每一項都通過才核准；任何一項不過，活動檔留在 `draft`，把沒過的項目回報給 Hank，由他決定。

## 會自動核准的活動

| 檢查 | 內容 |
|---|---|
| `not_on_hold` | 本資料夾沒有 `HOLD` 檔 |
| `structure` | 活動檔完整：時間順序正確、領取期限是開始後一個台北日曆月、獎勵項目都在該遊戲的清單內、信件長度在兩個伺服器的上限內、五種語言的文案齊全 |
| `calendar_occurrence` | 活動來自 `calendar.json` 的一筆節日，日期、時刻、等級與行事曆完全相同。臨時加的活動不會自動核准 |
| `starts_in_future` | 核准當下還沒到開始時刻。不補核准已經開始的活動 |
| `delivery_window` | 寄送期不超過 14 天 |
| `game_enabled:<遊戲>` | 該遊戲在 `games.json` 是啟用的 |
| `reward_matches_tier:<遊戲>` | 獎勵與該遊戲 `tiers` 裡對應等級的內容一模一樣。比較小的獎勵也不行：自動化不自己決定獎勵內容 |
| `reward_within_caps:<遊戲>` | 每個項目不超過 `rewardItems` 的 `max`；有標價的遊戲，換算總額不超過 `maxListedTwd` |
| `cooldown` | 同一款遊戲的前後兩檔活動至少隔 `minDaysBetweenCampaigns` 天（21） |

核准時把活動內容（時間、獎勵、信件、文案）算成雜湊記在 `approval.frozenSha256`。之後只要內容被改，`validate` 與 `deliver` 都會拒絕（`approved_campaign_was_modified`）；可以追加的只有寄送回條。

## 獎勵上限的依據

- **REBOUND：元素戰機**：`major` 等級與上限就是 Hank 核准過的 2026-10-07 普天同慶禮包（火花 6,000 點＋四種消耗卡各 1 張，標價換算約 NT$300）。`standard` 是它的一半左右（約 NT$150）。只發火花與四種消耗卡；永久自動射擊、免廣告這類永久權益不在清單裡，伺服器也會拒絕。
- **活字戰紀：雙城烽火**：只發金幣，`standard` 100、`major` 200、上限 300。一局收入約數十金，道具基礎價 5–30 金，神秘道具至少 12,000 金；這個量買得到幾件普通或稀有道具，碰不到神秘道具。共用造型是付費商品，不放進自動核准的獎勵。金幣沒有售價，文案不寫金額。

## 仍然要 Hank 決定的事

- 提高任何上限、修改 `tiers`、加入新的獎勵項目或新遊戲。
- 行事曆以外的活動，或已經錯過公告期的節日。
- 取消已核准的活動，或處理已寄出的信。
- 修改這份規則或 `lib/policy.js`。

## 對外文字的規矩

沿用先前公告的寫法，由 `lib/copy.js` 統一產生：

- 寄出數不等於領取數，公告只寫「已寄出 N 封」並註明核對時間。
- 有標價的獎勵寫「商品標價換算約 NT$…，非現金價值」；沒有標價的不寫金額。
- 期限一律寫到台北時間的日期與時刻。
- 回條出來之前，公告寫「寄送數量核對後會更新在這裡」，不預估數字。

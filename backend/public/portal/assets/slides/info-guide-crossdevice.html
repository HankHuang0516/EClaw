🛡️ Guide / Cross-Device Messaging

跨裝置訊息：外部訊息進 Bot 前的第一道門

當客戶透過 Public Code 對你的代理說話，Cross-Device Messaging 會先判斷 誰能進來、什麼內容能通過、多久能發一次。

🚦黑白名單與名片夾封鎖，讓來源先被授權或拒絕。
🧹禁用詞、媒體類型與預注入指令，控制訊息內容與上下文。
⏱️每位發送者獨立冷卻，避免外部窗口被洗版或濫用。

把公開連結變成可控入口

外部訊息不會直接打進 Bot；它先經過 gate，再把合規內容交給代理處理。

6GATE CHECKS
👤External User從代理窗口、好友或公開連結送訊息。
→
🛡️Cross-Device Gate套用封鎖、名單、內容、格式與速率規則。
→
🤖Bot Runtime只接收通過檢查、可安全處理的訊息。
Evaluation order Card block → Blacklist → Whitelist → Words → Media → Rate limit 任何一關不通過就拒絕，可回自訂拒絕訊息；通過後才交給 Bot 執行。
Pre-inject：補上情境與工作指令
Reject message：清楚回覆拒絕原因
Allowed media：限定 text/photo/voice/file
防騷擾封鎖特定 public code 或敏感關鍵字。
VIP 服務白名單模式只讓指定來源進入。
情境預設每則外部訊息自動帶入代理規則。
Cross-Device Messaging 讓 Bot 的公開入口既能被看見，也能被治理。

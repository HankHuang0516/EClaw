HOW IT WORKS

Codex asks. The manager schedules. Your test runs safely.

Builds and unit tests stay on the host. Runtime checks borrow one device or an atomic multiplayer group, then release automatically.

1CodexRequests runtime validation
→
2ManagerChecks pressure + FIFO
→
3Assigned deviceRuns, verifies, releases
◇

Warm shared devices

Tasks borrow manager-owned devices in turn. Apps and data remain for the next borrower.

↯

Fair under load

A 40-minute total budget supports long tests; a waiting task still triggers a safe yield at 2 minutes.

⌁

Multiplayer ready

Request two or more same-platform devices as one atomic FIFO group.

✓

Guaranteed release

Supervised work releases on success, failure, interruption, timeout, or safe yield.

AFTER INSTALL

The dashboard opens. Quick Start takes it from there.

A five-step guide explains when Codex should request a simulator, how automatic release works, and what happens when a task bypasses the shared lane.

1

A visible app entry

Keep Simulator Manager visible in the Dock, or reopen it from Applications and the macOS menu bar.

2

Built-in lessons

Replay Quick Start from the dashboard’s question-mark button whenever a task needs the rules.

3

One-click bypass monitor

The dashboard runs a read-only scan and separates attributable bypass activity from registration, observability, or overlapping-process gaps.

4

Your language, automatically

The native dashboard follows the device language by default, with persistent English and Traditional Chinese choices.

DEFAULT

Warm shared pool

Manager-owned devices stay warm and retain data for the next borrower.

MULTIPLAYER

Atomic device groups

Request N devices together; the task waits without holding a partial group, then releases every device after testing.

⌾

Local by design

Scheduling state, device identities, and test output stay on your Mac. Simulator Manager has no account, cloud service, analytics, or telemetry.
